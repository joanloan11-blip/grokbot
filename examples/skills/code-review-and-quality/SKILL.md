# Code Review and Quality

## Обзор
Пятиосевой ревью с гейтами качества. Ревью ловит баги, утечки и сложность до мержа — не после.

## Пять осей ревью
1. **Корректность** — делает ли код то, что заявлено? Граничные случаи, null/пусто, ошибки, конкурентность.
2. **Читаемость** — понятны ли имена и структура? Соответствует ли стилю соседнего кода? Нет ли "умного" кода без нужды?
3. **Тесты** — покрыто ли новое поведение? Есть ли регрессионный тест на баг? Не хрупкие ли тесты?
4. **Безопасность** — см. security-and-hardening: ввод, права, секреты, SQL-инъекции, XSS.
5. **Производительность** — см. performance-optimization: N+1 запросы, лишние аллокации, блокирующие вызовы в горячем пути.

## Чек-лист перед одобрением
- [ ] Изменения минимальны и по задаче (нет посторонних рефакторингов)
- [ ] Нет случайных артефактов: debug-логов, закомментированного кода, `console.log`, закомментированных тестов
- [ ] Нет секретов и ключей в коде/конфигах
- [ ] Обработаны ошибки и граничные случаи
- [ ] Тесты зелёные, сборка/линтер/типы проходят
- [ ] Нет мёртвого кода и неиспользуемых импортов
- [ ] Обновлена документация, если менялось поведение

## Как давать замечания
- Разделяй блокеры и нитпики, помечай явно
- Объясняй почему, а не только "так лучше" — конкретный сценарий, в котором сломается
- Предлагай альтернативу вместе с проблемой
- Хвали хорошие решения — это не формальность

## Как реагировать на ревью
- Не спорь ради спора, но и не соглашайся sycophantically с неверным замечанием — аргументируй
- Если переопределяют — принимай решение с полной информацией, но зафиксируй риск

## Definition of Done
Изменение готово, только если: тесты проходят, регрессий нет, поведение проверено в рантайме, документация обновлена, нет посторонних диффов.
