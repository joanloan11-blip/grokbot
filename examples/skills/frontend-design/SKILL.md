# Frontend Design

## Обзор
Подход дизайн-лида студии, которая даёт каждому клиенту узнаваемую визуальную идентичность. Клиент уже отверг шаблонные варианты: делай осознанные, «со мнением» решения по палитре, типографике и раскладке, специфичные для брифа.

## Отталкивайся от сути
Если в брифе не сказано, что это за продукт — определи сам и подтверди у клиента. Отрасль, материал, среда и язык предмета — источник отличительных визуальных решений. Верстка для игрушки для девочек 8–11 отличается от дашборда для финансовых аналитиков. Строь на реальном содержании брифа.

## Принципы
- **Герой**: первое, что видит гость. Открой самой характерной вещью предмета: заголовок, изображение, анимация, живая демо. «Большая цифра с маленькой подписью и градиент» — дефолт, используй только если это действительно лучшее решение.
- **Типографика = характер**. Одна—две гарнитуры, если две — явно различимые. Сознательные гарнитуры и ясная шкала (Elements of Typographic Style), осмысленные веса, ширина, трекинг.
- **Длина строки** < 80 символов (для serif чуть длиннее, line-height больше).
- **Избегай дефолтных типографских приёмов** (маркеры сгенерированной страницы): акцент одного слова в заголовке, ALL CAPS для лейблов, лишние лейблы над контентом.
- **Структура = информация**: обводки, нумерация, разделители кодируют реальный смысл. Числовые маркеры (01/02/03) — только если контент действительно последовательность.
- **Анимация** — дозированно, чтобы привлечь внимание. Один оркестрованный момент на загрузку лучше, чем разбросанные fade-up на каждом блоке и hover на каждой карточке. Анимация в ответ на действие — приветствуется.
- **Копирайтинг** тоже часть дизайна; если контента нет — придумай осмысленный, не шаблонный.

## Признаки сгенерированного дизайна (не используй по умолчанию)
1. кремовый фон (~#F4F1EA) + контрастный serif + терракота (~#D97757)
2. почти чёрный фон + кислотный зелёный/алый акцент
3. газетная раскладка, hairline-линии, нулевой радиус, плотные колонки
4. SaaS-карточки: одинаковые скруглённые карточки, один радиус на всё, одинаковая серая тень, градиентные заливки
5. шаблонный хром: ALL-CAPS eyebrow над каждым заголовком, мета-строки через «·», лейблы «СЛОВО — фрагмент», #0B0B0B вместо чёрного, моноширинный для мелких меток, «→» у кнопок и ссылок

Это допустимо, если бриф просит. Где бриф оставляет свободу — не трать её на эти дефолты.

## Процесс: план → сверка с брифом → сборка → критика
1. План: компактная система токенов — цвет (4–6 именованных hex), типографика и роли, раскладка (ASCII-вайрфреймы, выравнивание), принципы.
2. Сверь план с брифом: если часть читается как дефолт для любой похожей страницы — переработай, скажи что и почему.
3. Сборка: следи за специфичностью CSS-селекторов — легко получить классы, гасящие друг друга (особенно type-селектор .section и element-селектор .cta); часто это отступы между секциями.

## Сдержанность и самокритика
Смелость — в одном месте. Один запоминающийся элемент, вокруг тихо и дисциплинированно; убери декор, который не служит брифу. Нижняя планка без объявления: адаптив до мобильного, видимый focus с клавиатуры, уважение reduced motion, доступная контрастность. Скриншоть и критикуй по ходу.
