# ops — эксплуатация сервера qastom (217.197.114.108)

## Автоуборка диска

`disk-cleanup.sh` — регулярная безопасная уборка Docker-мусора. Установлен на сервере:
`~/maintenance/disk-cleanup.sh`, журнал `~/maintenance/disk-cleanup.log`.

Cron (пользователь `rus`):
```cron
*/10 * * * * $HOME/maintenance/disk-cleanup.sh watchdog >> $HOME/maintenance/cron.log 2>&1
20   4 * * * $HOME/maintenance/disk-cleanup.sh daily    >> $HOME/maintenance/cron.log 2>&1
```

### Что убирается

| Объект | В плановом режиме (`daily`) | При нехватке места (`watchdog`) |
|---|---|---|
| Остановленные контейнеры | старше 7 дней | старше 7 дней |
| Висячие образы `<none>` | старше 12 ч | старше 12 ч |
| Неиспользуемые образы | старше 7 дней | 48 ч → 24 ч → 1 ч → все неиспользуемые |
| Кэш сборки (buildkit) | старше 48 ч | старше 24 ч, при критике — весь |
| Журнал systemd | vacuum до 300 МБ | — |

Пороги занятости диска: уборка начинается при **82%**, эскалация на 88% и 92%,
критическое уведомление в Telegram — если после уборки всё ещё ≥ 92%.

### Почему это безопасно для приложений

* **Тома (volumes) и сети не чистятся никогда** — базы данных и данные приложений неприкосновенны.
* `docker prune` не удаляет образы, на которые ссылается хоть один контейнер (запущенный или остановленный).
* Остановленные контейнеры удаляются только через 7 дней (это пересоздаваемые compose-контейнеры).
* При экстренной уборке образы **моложе 1 часа** сохраняются, чтобы не сорвать идущий деплой.
* Работающие контейнеры не перезапускаются, docker-демон не трогается.

### Разовая root-настройка (уже выполнена/выполнить один раз)

```bash
sudo bash ~/maintenance/root-setup.sh
```
Ограничивает журнал systemd 500 МБ, делает первый vacuum и разрешает `rus` запускать
только `journalctl --vacuum-size=*` без пароля. Приложения не перезапускаются.

### Проверка вручную

```bash
bash ~/maintenance/disk-cleanup.sh dry       # только показать состояние
bash ~/maintenance/disk-cleanup.sh watchdog  # прогнать уборку сейчас
tail -30 ~/maintenance/disk-cleanup.log
```
