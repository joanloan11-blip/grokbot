# QASTOM AGENT

Локальный ассистент с чатом, любым LLM-провайдером, MCP-серверами и навыками. Один и тот же интерфейс открывается в браузере и в окне Electron. Ключи API остаются на сервере и после сохранения в браузер не возвращаются.

**Документация:** [справка для пользователей](docs/USER-GUIDE.md) — агенты, плагины, навыки и коннекторы с примерами; [позиционирование и тарифы](docs/POSITIONING.md) — внутреннее.

## Что нужно

- Node.js 22+
- pnpm 10 (`corepack enable`, затем `corepack prepare pnpm@10.33.4 --activate`)

## Запуск веб-версии

```bash
cp .env.example .env   # необязательно
pnpm install
pnpm dev
```

- Интерфейс: http://127.0.0.1:5173
- API: http://127.0.0.1:8787

`pnpm dev` поднимает сервер и Vite. В чате сразу отвечает демо-модель: сеть и ключ не нужны.

Проверка, линт и сборка:

```bash
pnpm test
pnpm lint
pnpm typecheck
pnpm build
```

## Десктоп

Оболочка — Electron. Она открывает тот же интерфейс. В разработке окно ждёт Vite на порту 5173, сервер должен быть запущен (его тоже стартует команда ниже).

```bash
pnpm dev:desktop
```

Сборка каталога приложения для Linux (без установщика):

```bash
pnpm build
```

Готовое приложение: `apps/desktop/release/linux-unpacked/mayak`. В этой сборке процесс Electron сам поднимает сервер и раздаёт статику. Данные лежат в каталоге userData Electron, не в `./data` репозитория.

Сборка Linux на этой машине не подписывается и не делает установщик. Установщики macOS и Windows собирает GitHub Actions (workflow **Desktop installers**) на каждый push и на теги `v*`:

- macOS: `dmg` и `zip` для arm64 (Apple Silicon) и x64 (Intel), без подписи Apple;
- Windows: NSIS (`.exe`) и `zip` для x64, без подписи.

Артефакты лежат во вкладке Actions у соответствующего запуска (`mayak-macos`, `mayak-windows`). Если push — это тег `v*`, те же файлы попадают в GitHub Release. Имена файлов: `Mayak-<версия>-mac-<arch>.dmg` / `.zip` и `Mayak-<версия>-win-x64.exe` / `.zip`.

### Неподписанное приложение на macOS

Сборка не подписана разработчиком Apple, поэтому Gatekeeper может написать, что приложение от неизвестного разработчика или «повреждено».

1. Скачайте `Mayak-…-mac-arm64.dmg` на Apple Silicon или `Mayak-…-mac-x64.dmg` на Intel.
2. Откройте образ и перетащите Mayak в «Программы».
3. Первый запуск: в Finder щёлкните Mayak **правой кнопкой** → **Открыть** → ещё раз **Открыть**. Двойной щелчок в первый раз часто блокируется.
4. Если система всё равно не пускает, снимите карантин в Терминале и повторите правый клик → «Открыть»:

```bash
xattr -dr com.apple.quarantine /Applications/Mayak.app
```

Для zip распакуйте архив и выполните ту же команду с путём к `Mayak.app` внутри папки.

На Windows SmartScreen для неподписанного `.exe` показывает предупреждение: «Подробнее» → «Выполнить в любом случае».

## Файлы, голос, поиск, навыки и рабочая папка

- **Фото и файлы.** Скрепка в поле ввода прикрепляет картинки (PNG, JPEG, WebP, GIF) и документы (PDF, TXT, MD, CSV, DOCX, XLSX) до 8 МБ. Картинки видят модели OpenAI-совместимых провайдеров, Anthropic и Gemini (до 6 последних картинок в истории). DeepSeek и демо-модель получают пометку, что картинку нужно смотреть другой моделью. Текст документов дописывается к сообщению.
- **Голосовой ввод.** Кнопка микрофона записывает речь и вставляет распознанный текст в поле. Нужен `WHISPER_URL`: адрес whisper.cpp server (`http://whisper:8080`, запрос идёт на `/inference`) или OpenAI-совместимый `…/v1` (тогда `/audio/transcriptions`, ключ в `WHISPER_API_KEY`, модель в `WHISPER_MODEL`). Запись перекодируется в WAV через ffmpeg (есть в Docker-образе).
- **Поиск по чатам.** Поле в боковой панели ищет по тексту всех сообщений и названиям чатов (от 2 символов) и показывает фрагмент с совпадением.
- **Навыки, которые пишет агент.** Инструмент `skill_manage` (list / create / update) сохраняет удачную процедуру как `SKILL.md` и сразу подключает навык к агенту. Писать навыки может только администратор; при включённых подтверждениях вызов ждёт одобрения.
- **Папка на компьютере (по умолчанию).** Новый агент по умолчанию работает в папке на
  компьютере пользователя (File System Access API): файлы и память не занимают сервер. Переключатель
  «💻/☁» в поле ввода хранит выбор отдельно для каждого агента; выбор «☁» отправляет файлы в
  `DATA_DIR/workspaces/<пользователь>/<агент>` на сервере.
- **Точки отката файлов.** Перед ходом агента с инструментами записи снимается архив рабочей
  папки (`DATA_DIR/checkpoints/<чат>`, без `node_modules`/`.git`/`.venv`), а под ответом с
  изменениями появляется кнопка «Отменить изменения хода» — `POST
  /api/conversations/:id/checkpoints/:id/restore`. Хранятся 10 точек на чат и не дольше недели.
  В режиме «папка на компьютере» откат не поддерживается.
- **Терминал в чате.** Кнопка «🖥 Терминал» запускает команду пользователя в рабочей папке
  агента и стримит stdout/stderr: `POST /api/workspace/terminal` (SSE) → runner
  `POST /stream` (NDJSON). Команду можно остановить оборвав поток; вывод обрезается на 1 МБ,
  таймаут до 10 минут, тот же sandbox-пользователь и egress. Доступ: Настройки → Общие —
  «Песочница кода» и «Терминал доступен клиентам» (`code_sandbox`, `terminal_access=all|staff`).
  Если runner старый (без `/stream`),
  сервер откатывается на `/run` и отдаёт вывод одним куском.
- **Превью статики.** `GET /api/preview/:scope/*` отдаёт файлы рабочей папки агента/проекта
  (index.html, ассеты, собранный `dist/`) с `Content-Security-Policy: sandbox` без
  `allow-same-origin` — скрипты превью не видят cookie и API. UI: кнопка «👁 Превью» и iframe
  в чате. Живой dev-сервер (HMR/прокси портов) — следующий шаг.
- **План агента.** `todo_write` пишет список дел в таблицу `todos`; в чате над вводом показывается
  панель «📋 План» с прогрессом и чекбоксами (`GET /api/agents/:id/todos`,
  `PATCH /api/todos/:id`).
- **Параллельные чтения.** Read-only инструменты помечены `parallelSafe` и выполняются
  одновременно (`apps/server/src/agent/loop.ts`), запись и опасные действия — по-прежнему
  последовательно.
- **Память на компьютере.** В локальном режиме `memory_read`/`memory_write`/`remember`/`recall`
  работают с файлом `.qastom/memory/<agentId>.json` в выбранной папке (общие заметки —
  `shared.json`), в базу сервера ничего не пишется. Память не добавляется в каждый запрос, поэтому
  на цену сообщений её размер не влияет.
- **Рабочая папка.** У каждого агента своя папка `DATA_DIR/workspaces/<пользователь>/<агент>`. Инструменты `workspace_list`, `workspace_read`, `workspace_write`, `workspace_edit`, `workspace_delete` не выходят за её пределы, правки показываются в чате цветным диффом. `shell` запускает команду в Docker-песочнице без сети с папкой в `/work`, только если администратор включил песочницу кода. Если сервер сам работает в Docker и пользуется Docker хоста, укажите в `MAYAK_WORKSPACE_HOST_DIR` путь к `DATA_DIR/workspaces` на хосте; образ задаётся `MAYAK_SHELL_IMAGE` (по умолчанию `python:3.12-alpine`).

## Менеджеры: личные агенты и проекты

**Свои модели.** Менеджер добавляет свой ключ в меню пользователя → **Мои модели**: OpenAI, DeepSeek, NVIDIA, OpenRouter, Anthropic, Gemini или любой OpenAI-совместимый провайдер по https. Модели сразу появляются у него в выборе модели и в его личных агентах. Ключ не видит и не использует никто другой, включая администратора. В общих настройках, расходах ключей, картинках и общем каталоге моделей личные провайдеры не участвуют. Адреса во внутренней сети сервера и обычный http запрещены. Дневные лимиты менеджера действуют и на его ключи.

- **Личные агенты.** Менеджер сам создаёт агентов («Новый агент»): их видит только он, модель — из открытых ему админом. MCP и GitHub подключает администратор у общих агентов. Админ видит все агенты и может сделать личного агента общим (кнопка «Сделать общим для команды»).
- **Проекты.** Блок «Проекты» в боковой панели: клиент, сделка или задача с контекстом и правилами. Чаты проекта собраны вместе, агент получает контекст проекта в каждом из них, рабочая папка у проекта одна. Проекты личные.

## МойСклад: ответ клиенту с наличием

Администратор вставляет токен МойСклад в **Настройки → Общие** (или `echo <токен> | node apps/server/dist/index.js moysklad-token`). Агентам становится доступен инструмент `stock_lookup` (только чтение): наличие, резерв, цена и остатки по складам. Шаблон агента «Продажи: ответ с наличием» готовит ответ клиенту по живому складу и предлагает сопутствующие товары, которые есть в наличии.

## Картинки

Инструмент `generate_image` рисует картинку по описанию или правит приложенные фото (OpenAI Images: `gpt-image-2`, `gpt-image-1.5`, `gpt-image-1`, `gpt-image-1-mini`). Картинка сохраняется в файлах чата и показывается в ответе. Администратор включает генерацию, выбирает OpenAI-провайдера, модель, качество и дневной лимит на пользователя в **Настройки → Общие → Картинки**. По умолчанию генерация включена, если есть провайдер на api.openai.com с ключом; запросы идут через `LLM_PROXY_URL`, если он задан.

## Почта и Telegram-ассистент

При регистрации каждому пользователю создаются два готовых агента: **✉️ Почтовый агент** и
**🎩 Джарвис**. Они же есть в шаблонах («Новый агент»), поэтому их можно добавить и в старый
аккаунт вручную.

- **Почта (IMAP).** Настройки → **Почта**: пресеты Яндекса, Mail.ru, Gmail, Outlook, iCloud или
  свой сервер; порт, логин, пароль приложения, папка. Подключение проверяется сразу, пароль
  шифруется AES-256-GCM и в браузер не возвращается. Агент читает ящик через инструмент
  `mail_digest` (только чтение, письма помечены как недоверенные данные). Рутина «Утренняя
  почта» по умолчанию в 9:00 создаётся при регистрации и включается после подключения ящика;
  время меняется в Настройки → Почта, результат приходит в чат и в личный Telegram.
- **Личный Telegram-бот.** Настройки → **Telegram**: токен из @BotFather и свой числовой ID
  (@userinfobot). Бот работает long-polling'ом (`apps/server/src/telegram-bots.ts`), отвечает
  только владельцу, понимает текст и голосовые (скачивает файл, перекодирует через ffmpeg и
  распознаёт через `WHISPER_URL`), отвечает текстом, режет длинные ответы на части. Команды
  `/start`, `/help`, `/new`. Переписка видна в приложении в чате «Telegram: Джарвис»; результаты
  рутин уходят в этот же бот. Токен хранится зашифрованным.
  Если с сервера нет прямого доступа к `api.telegram.org` (российские VPS), задайте
  `TELEGRAM_PROXY=socks5://…` — запросы к Telegram пойдут через SOCKS5-туннель (на qastom это
  уже существующий `llm-relay`, см. `docker-compose.qastom.yml`). Внутренние адреса
  (whisper, runner) через прокси не ходят. Старый общий бот команды
  (`/api/admin/telegram` + `/start <код>`) оставлен для ранее привязанных чатов.

Оба канала — личные для каждого пользователя, секреты лежат в `settings` (таблица
`telegram_bots` — для ботов). Новых npm-зависимостей нет: IMAP-клиент и Telegram-клиент написаны
на стандартной библиотеке Node.

## amoCRM, МойСклад, Авито и браузер (сервер qastom)

Готовые MCP-серверы запущены рядом с Маяком в docker-сети `mayak_mcp` и наружу не открыты. Конфигурация лежит в `deploy/qastom-mcp`, секреты в git не попадают.

| Сервер в Маяке | Что это | Доступ |
| --- | --- | --- |
| `amocrm` | [amocrm-mcp](https://github.com/cAIborg-ai/amocrm-mcp), контейнер `amocrm-mcp` | чтение и запись: сделки, контакты, задачи |
| `moysklad` | [moysklad-mcp-ru](https://github.com/ilyautov/moysklad-mcp-ru) | только чтение (`MOYSKLAD_ALLOW_WRITE` не задан) |
| `avito-<кабинет>` | [avito-mcp](https://github.com/elchin92/avito-mcp), по контейнеру на кабинет | 29 инструментов: чаты, объявления, статистика, баланс, отзывы. Отправка сообщений и ответы на отзывы требуют `meta_confirm_action` |
| `browser` | [Playwright MCP](https://github.com/microsoft/playwright-mcp), headless Chromium в отдельной сети `mayak_browser` | открыть страницу, прочитать, кликнуть, заполнить поле |

Подключить сервер к агенту: **Агент → MCP-серверы**. В шаблонах «Аналитик рынка», «Аналитик конкурентов» и «Продажи» нужные серверы отмечены сразу. Каждый сервер добавляет агенту 25–36 инструментов, а их описания уходят в каждый запрос к модели. Поэтому подключайте агенту только то, что ему нужно.

Обновить или добавить кабинет Авито: положите `avito/secrets/<кабинет>.env` (`Client_id`, `Client_secret`, `Profile_id`) и запустите `bash deploy.sh`. Затем зарегистрируйте сервер в Маяке, как в `register.cjs`.

Авито и ZZap показывают headless-браузеру проверку «Доступ ограничен» / «проверяем ваш браузер». Агент её не обходит. Дром открывается.

## Расходы

Меню пользователя → **Расходы**. Маяк записывает каждый вызов модели: какой бот (агент), какой пользователь, какой ключ и модель, сколько токенов на входе, сколько из кэша и сколько на выходе. Токены берутся из ответа провайдера (`usage` у OpenAI-совместимых API, включая DeepSeek, OpenRouter и xAI; `usage` у Anthropic; `usageMetadata` у Gemini). Если провайдер их не прислал, Маяк оценивает их по длине текста и помечает знаком ≈. Картинки считаются отдельно, по `usage` ответа OpenAI Images.

Стоимость = токены × цена модели. Цены по умолчанию лежат в `apps/server/src/pricing.ts`; администратор меняет их кликом по цене в блоке «По ключам». Администратор видит всех пользователей, ботов и ключи, а также баланс тех ключей, которые его отдают (DeepSeek, OpenRouter, Moonshot). Остальные пользователи видят только свои расходы по ботам. Периоды: сегодня, 7 дней и 30 дней (по UTC).

## Экономия токенов

- **Коннекторы по требованию.** Если у агента больше 15 MCP-инструментов, модель видит не все схемы, а каталог «коннектор: список инструментов» и два инструмента: `connector_tools` (схемы нужного коннектора) и `connector_call` (вызов). Порог — настройка `lazy_mcp_threshold`.
- **Сжатие истории.** Последние ~14 сообщений идут целиком; если старая часть длиннее ~14 тыс. символов, она заменяется кратким пересказом (делает та же модель, результат кэшируется в `chat_summary:<id>` и дописывается по мере роста чата).
- **Старые результаты инструментов** (ответы amoCRM, МойСклад, страницы) в истории обрезаются до 1 500 символов, текущий шаг — целиком. Старые текстовые файлы — до 2 000 символов.
- **Картинки** отправляются только из двух последних сообщений пользователя; раньше модель их уже видела.

## Индикатор расхода и лимиты

Слева на панели иконок — кольцо расхода, как в Codex: внешнее — неделя, внутреннее — день, цифра — процент недельного лимита. По клику: проценты, доллары, токены, число запросов и время сброса. День начинается в 00:00, неделя — в понедельник 00:00 по времени сервера (`TZ`, у нас Екатеринбург). Лимиты в долларах задаёт администратор в **Команде**: общий по умолчанию и свой для каждого человека. Когда лимит исчерпан, запросы к моделям останавливаются до сброса. Без лимита индикатор показывает просто сумму.

## Оркестратор

Агент из шаблона **🧭 Оркестратор** (или любой агент с инструментом `delegate`) раздаёт независимые подзадачи другим агентам или копиям себя (`agent: "self"`). До 6 подзадач, по 3 параллельно, у каждой 5 минут. Каждая подзадача идёт в отдельном чате того же проекта; в ответе видна карточка по каждой подзадаче со статусом, временем, результатом и ссылкой на её чат. Субагенты дальше не делегируют. Если включено подтверждение инструментов, `delegate` тоже требует подтверждения.

## Как добавить модель

1. Откройте **Настройки → Модели → Добавить провайдера**.
2. Выберите тип:
   - **OpenAI-совместимый** — OpenAI, OpenRouter, Groq, Ollama, LM Studio и любой другой `/v1`. Базовый URL без хвоста метода, например `https://openrouter.ai/api/v1` или `http://127.0.0.1:11434/v1`.
   - **Anthropic** — по умолчанию `https://api.anthropic.com`.
   - **Google Gemini** — по умолчанию `https://generativelanguage.googleapis.com/v1beta`.
   - **DeepSeek** — пресет OpenAI-совместимого API: базовый URL `https://api.deepseek.com`, модели `deepseek-chat` и `deepseek-reasoner`. У `deepseek-reasoner` поток `reasoning_content` показывается в чате свёрнутым блоком «Рассуждение», отдельно от ответа, и сохраняется в истории. В модель этот текст обратно не отправляется. В системном промпте есть просьба рассуждать на языке последнего сообщения пользователя, а не на английском по умолчанию.
3. Вставьте API-ключ и идентификаторы моделей, по одному на строку (`gpt-4o-mini`, `claude-sonnet-4-5`, `gemini-2.5-flash`, имя модели Ollama и т.д.).
4. Сохраните. Ключ пишется в SQLite на сервере. В ответах API его нет, только признак «ключ задан». Пустое поле при редактировании ключ не стирает.
5. В шапке чата выберите модель. Ответы идут потоком, вызовы инструментов видны карточками.

Тот же провайдер можно создать при первом запуске переменными из `.env.example`: `MAYAK_OPENAI_BASE_URL`, `MAYAK_OPENAI_API_KEY`, `MAYAK_OPENAI_MODEL`.

Если в `.env` или в окружении задан `DEEPSEEK_API_KEY`, сервер при старте сам добавляет провайдер DeepSeek (ключ уже лежащий в базе не затирается). Новые чаты тогда по умолчанию идут в `deepseek-chat`. Файл `.env` не коммитьте.

Демо-модель понимает короткие команды, чтобы проверить инструменты без внешнего API:

- `skill summary` — загрузить навык
- `echo привет` — вызвать MCP-инструмент `echo`, если сервер `demo` включён
- `add 2 3` — сложить числа
- `tool <имя> <json>` — вызвать любой инструмент по имени или суффиксу имени

Настоящая модель вызывает инструменты сама, по их JSON-схеме.

### Проверка моделей (MCP)

В выборе модели в чате и у агентов показываются **только проверенные модели, которые отвечают**. Провайдер без нужного ключа скрыт целиком; модель, которая не ответила или ещё не проверена, не показывается. Демо-модель показывается всегда. Проверка идёт сама: после сохранения провайдера, через минуту после старта сервера и дальше раз в 3 часа для моделей, которые не проверялись больше суток (не ответившие по таймауту — повторно через час). Кнопка **Проверить все модели** — в Настройках → Модели; там же у каждого провайдера видно «В выборе в чате: X / Y».

После сохранения провайдера Маяк сам проверяет каждую его модель: отвечает ли она и умеет ли вызывать инструменты (MCP, склад, браузер). В выборе модели это видно сразу: `MCP ✓`, `без MCP`, `не отвечает`. Модели без ключа (Kilo, LLM7, OVHcloud), которые не отвечают, в выбор не попадают. Модели без MCP получают запрос без инструментов. Повторная проверка — кнопкой **Проверить модели** у провайдера или командой `node apps/server/dist/index.js check-models [провайдер]`. Лимиты запросов и таймауты моделью «не отвечает» не считаются.

### Бесплатные провайдеры

**Настройки → Модели → Бесплатные провайдеры** (и у менеджера в **Мои модели**) — каталог [awesome-free-llm-apis](https://github.com/mnfst/awesome-free-llm-apis) (CC0): Gemini, Groq, Mistral, Cohere, OpenRouter (`:free`), NVIDIA, Cloudflare, Z AI, Kilo, LLM7, OVHcloud и другие. «Подключить» подставляет адрес и бесплатные модели. Остаётся вставить ключ: у Kilo, LLM7 и OVHcloud он не нужен. Для каждого провайдера показано важное: логирует ли он промпты для обучения, нужна ли проверка личности, есть ли ограничения по региону. Снимок каталога лежит в `apps/server/src/free-llm-catalog.json`; администратор обновляет его с GitHub ссылкой «обновить список». Хосты, закрытые из России (Cohere, Groq, Kilo, OpenRouter, Cloudflare, NVIDIA), идут через `LLM_PROXY_URL`. В «Расходах» бесплатные модели из каталога стоят 0.

### NVIDIA (бесплатно)

Ключ с [build.nvidia.com](https://build.nvidia.com) начинается с `nvapi-`. Вставьте его в **Настройки → Модели**: Маяк сам определит NVIDIA (`https://integrate.api.nvidia.com/v1`) и загрузит модели. Первыми в списке идут DeepSeek, Kimi, GLM, Qwen и Nemotron. Из России NVIDIA отвечает 451, поэтому запросы к ней идут через `LLM_PROXY_URL`. В «Расходах» модели NVIDIA считаются бесплатными. Лимит бесплатного доступа — около 40 запросов в минуту на ключ; гарантий доступности нет, это доступ для разработки.

## Агенты

### Универсальные шаблоны и выбор ниши

Все девять шаблонов подходят для разных сфер: они не привязаны к автозапчастям, конкретной компании или площадке продаж. При создании агента на шаге **Ниша и задачи** можно выбрать сферу из списка, указать свою нишу и описать задачи и желаемый результат. Если поля оставить пустыми, агент остаётся универсальным. Контекст добавляется к системным инструкциям и сохраняется вместе с агентом; позже его можно изменить в настройках агента. Базовый промпт доступен в разделе **Дополнительно: инструкции агента**.

Навыки и коннекторы выбираются отдельно: отраслевые навыки и MCP больше не подключаются шаблонами автоматически. Существующие агенты и их настройки не переписываются.

**Новый агент** (панель иконок → 🤖 или «+» у агентов): шаблон или **✨ Свой агент** с нуля. На шаге «Инструменты» три раздела:
- **Навыки** — инструкции из `data/skills`, агент загружает их под задачу.
- **Коннекторы** — MCP-серверы (amoCRM, МойСклад, Авито, браузер…). Каждый добавляет 25–36 инструментов в каждый запрос, поэтому подключайте только нужные. Менеджер видит свои коннекторы и общие, которые администратор открыл ему галочкой **«Доступен менеджерам»** (Настройки → MCP). Адрес и ключи общих коннекторов менеджеру не показываются. Свой коннектор менеджер добавляет в **Мои модели и коннекторы**: только Streamable HTTP по https во внешний интернет (команды на сервере запускает только администратор), до 10 штук; видит и использует его только он.
- **Плагины** — встроенные возможности: интернет, склад, картинки, рабочая папка, код, память, команда агентов, расписание, страницы, свои навыки, GitHub. Выключенные плагины модель не видит.

В боковой панели список агентов. У каждого свои чаты, модель, системный промпт, набор навыков и MCP-серверов, память и расписание.

**Новый агент** открывает мастер: шаблон, имя и эмодзи, роль, промпт, модель, галочки навыков и MCP. Шаблоны: Ассистент, Исследователь, Редактор, Инженер. Их можно сразу поправить.

**Настроить агента** меняет те же поля. Там же:

- **Память** — заметки агента. Он сам читает и пишет их инструментами `memory_read` и `memory_write`. Заметки общие для всех чатов этого агента у одного пользователя и не смешиваются с другими агентами и другими людьми.
- **Расписание** — cron из пяти полей (минута, час, день, месяц, день недели; `0` и `7` — воскресенье) и промпт. Сервер проверяет расписание примерно раз в 20 секунд и кладёт ответ в чат «Расписание: название». Кнопка «Запустить сейчас» делает то же без ожидания cron.

Агенты пишут друг другу инструментом `send_to_agent` (`agent` — имя, `message` — текст). Ответ собеседника возвращается в текущий чат, а переписка остаётся у получателя в чате «От: имя отправителя». Цепочка дальше одного прыжка не идёт, чтобы агенты не зациклились.

Демо-модель понимает и эти инструменты: `tool memory_write {"key":"project","content":"заметка"}` и `tool send_to_agent {"agent":"Редактор","message":"привет"}`.

Последнего агента удалить нельзя. Включённый MCP-сервер попадает в инструменты только если он отмечен у агента. У «Маяка», созданного при первом запуске, отмечены серверы, которые уже были в базе.

## Как добавить MCP-сервер

Настройки → MCP. Два транспорта официального `@modelcontextprotocol/sdk`: **stdio** и **Streamable HTTP**.

В базе уже лежит выключенный сервер `demo` — маленький процесс из `examples/demo-mcp-server` с инструментами `echo` и `add`. Включите его переключателем. В чате напишите `echo привет из Маяка`.

Свой сервер — кнопкой «Добавить сервер» или вставкой JSON в формате `mcpServers` (как в Claude Desktop и Cursor):

```json
{
  "mcpServers": {
    "demo": {
      "command": "node",
      "args": ["examples/demo-mcp-server/server.mjs"],
      "enabled": true
    },
    "remote": {
      "url": "http://127.0.0.1:3000/mcp",
      "headers": { "Authorization": "Bearer …" }
    }
  }
}
```

`enabled: false` оставляет сервер в списке, но не подключает его. Поле есть расширение Маяка: обычные конфиги без него тоже принимаются и включаются. Значения `env` и `headers` после сохранения в браузер приходят как `••••••`. Если отправить маску обратно, сохранённый секрет не затирается.

Имена инструментов, которые видит модель, выглядят как `mcp__<сервер>__<инструмент>`. Встроенный `load_skill` зарезервирован за навыками.

## Как добавить навык

Навык — папка с файлом `SKILL.md`. При первом запуске примеры копируются в `data/skills/` (или `$DATA_DIR/skills`).

```markdown
---

description: Кратко пересказывает текст
enabled: true
---

# Инструкции

Когда просят пересказ, сохрани язык оригинала и не добавляй новых фактов.
```

Имя папки — латинские буквы, цифры, `-` и `_`. Включённые навыки попадают в системный промпт как имя и описание. Полный текст модель забирает инструментом `load_skill`. Создать и править навык можно в **Настройки → Навыки** или прямо в файле: сервер читает каталог при каждом запросе.

Проверка демо-моделью: `skill summary`.

## Несколько пользователей

По умолчанию сервер однопользовательский: регистрация не нужна, десктоп так и работает (`MAYAK_SINGLE_USER=1` в собранном приложении). Для филиалов включите `MAYAK_AUTH=1`.

- Вход по почте и паролю. Пароль хранится как scrypt, сессия — JWT в httpOnly-cookie `mayak_session`.
- Первый зарегистрированный становится администратором. Следующие — менеджеры со статусом «ждёт подтверждения», пока админ их не включит.
- Админ приглашает менеджера и получает одноразовый токен (почта сама не уходит — сервер без SMTP). Менеджер вводит токен и свой пароль.
- Агенты, провайдеры, MCP и навыки общие и правятся только админом. Провайдер добавляется в настройках с API-ключом: ключ остаётся на сервере и менеджеру не отдаётся. У каждой модели провайдера есть переключатель «менеджерам». Пока он выключен, менеджер эту модель не видит и сервер отвечает 403. У конкретного менеджера можно сузить набор: «Только выбранные модели».
- В поле ввода чата у менеджера, рядом с кнопкой отправки, список только разрешённых моделей. Выбор сохраняется в чате и уходит с каждым сообщением.
- Журнал расхода за сегодня показывает, какая модель сколько раз вызывалась.

## GitHub

В **Настройках → GitHub** администратор сохраняет personal access token (права `repo` или fine-grained: содержимое, задачи и pull request). Токен шифруется AES-256-GCM ключом от `JWT_SECRET` и в браузер больше не возвращается. Если заданы `GITHUB_CLIENT_ID` и `GITHUB_CLIENT_SECRET`, вместо вставки токена доступна кнопка входа через OAuth App. Секрет приложения тоже только в окружении.

Импорт MCP: вставьте `https://github.com/owner/repo` или выберите репозиторий из списка. Сервер скачивает tarball через API (не больше 20 МБ), смотрит `package.json` с `bin`, `pyproject.toml`, `Dockerfile` и JSON с `command` в README и предлагает команду. Ничего не запускается, пока админ не нажмёт «Добавить MCP-сервер». Галочка «Включить сразу» отдельно запускает процесс. Папки с `SKILL.md` можно забрать как навыки.

Кнопки официального GitHub MCP добавляют сервер выключенным: удалённый `https://api.githubcopilot.com/mcp/` или Docker-образ `ghcr.io/github/github-mcp-server`. Токен попадает в заголовки или env и в интерфейсе маскируется. Включите сервер в списке MCP, когда будете готовы его запустить.

В карточке агента отметьте репозитории. Тогда у агента появляются инструменты `github_list_repos`, `github_read_file`, `github_search_code`, `github_list_issues` и `github_list_pulls`. Они ходят в REST API только по отмеченным репозиториям. В многопользовательском режиме токеном и импортом занимается только админ, менеджеры пользуются уже подключёнными репозиториями.
- Чаты, память и расписания у каждого свои. Админ чужие переписки не читает, ему виден журнал вызовов модели и дневной лимит.
- Пустой лимит значит «без ограничения». Лимит считается с полуночи UTC, каждый вызов модели — одна запись. Сверх лимита сервер отвечает 429.

## Возможности агента

Поверх чата, MCP и навыков агент умеет:

- **Рутины.** Cron и секретный вебхук `/api/hooks/<токен>`. История запусков хранится. Инструмент `create_routine` создаёт рутину из чата.
- **Память.** `remember` пишет профиль, журнал или общую для всех агентов этого пользователя заметку. `recall` ищет по тексту. Старые `memory_read` / `memory_write` на месте.
- **Интернет.** `web_search` (SearXNG по `SEARXNG_URL` или Brave/Tavily, ключ задаёт админ) и `web_fetch` (HTML в markdown, не больше 1 МБ, без частных адресов и редиректов в них).
- **Подзадачи и дела.** `task` запускает субагента в фоне и пишет результат в тот же чат. `todo_write` ведёт список дел. Статусы задач: `GET /api/tasks`.
- **Страницы.** `create_page` сохраняет markdown-отчёт. Ссылка вида `/api/public/pages/<токен>` открывается без входа. Список: `GET /api/pages`.
- **Файлы.** Вложение к чату (`POST /api/conversations/:id/files`, поле `file`, до 8 МБ) извлекает текст из CSV, PDF, DOCX и XLSX. Скачивание: `GET /api/files/:id`. Картинки сохраняются и помечаются в тексте.
- **Песочница.** `run_code` для python или node только в Docker (`--network none`, память 256 МБ, 15 с). Пока админ не включит её в настройках, код не запускается и на хост не попадает.
- **Одобрения.** Если админ включил подтверждения, `send_to_agent`, `run_code` и вызовы MCP ждут карточку в чате. Имена в `approval_auto` через запятую проходят сразу.
- **Telegram.** Личный бот на пользователя: токен и Telegram ID в Настройки → Telegram (агент «Джарвис»), текст и голосовые, результаты рутин. Старый вариант с общим ботом (`/api/admin/telegram`, `/start <код>`) сохранён для прежних привязок.
- **Расход.** Каждый вызов модели пишет оценку токенов. В журнале админа есть сумма токенов и грубая стоимость. Лимит токенов на пользователя задаётся админом (`dailyTokenLimit` вместе с `userId`).

Поиск по названиям чатов — поле над списком. Тёмная и светлая тема и узкий экран уже были.

Новые переменные: `MAYAK_PORT` (снаружи, по умолчанию 8090 в `docker-compose.vps.yml`), `SEARXNG_URL`. Ключи поиска, токен Telegram и флаг песочницы хранятся в базе, не в репозитории.

Миграции только добавляют таблицы и колонки (`CREATE TABLE IF NOT EXISTS`, `ALTER TABLE ... ADD COLUMN`). Старые чаты и ключи не переписываются.

## Развёртывание на VPS

Сервер слушает `HOST` и `PORT` (по умолчанию `127.0.0.1:8787`). Для сети поставьте `HOST=0.0.0.0`. Локально остаётся SQLite (`DATA_DIR`). Для общей базы задайте `DATABASE_URL=postgres://user:pass@host:5432/mayak` — те же таблицы, без отдельной миграции вручную.

Образ и compose лежат в корне репозитория: приложение и Postgres 16. Для VPS есть `docker-compose.vps.yml`: снаружи порт `MAYAK_PORT` (по умолчанию 8090), внутри приложение слушает 8787.

```bash
# на сервере, в каталоге с репозиторием
export JWT_SECRET="$(openssl rand -hex 32)"
docker compose up -d --build
```

По умолчанию compose публикует порт `8787`. Перед боем смените `POSTGRES_PASSWORD`, `DATABASE_URL` и `JWT_SECRET` в `docker-compose.yml`. Первый открывший сайт человек регистрируется и становится админом.

HTTPS удобнее отдать обратному прокси, а не процессу Node. В compose есть профиль `https` с Caddy: он сам получает сертификат Let's Encrypt и проксирует на `app:8787`. Домен должен смотреть на VPS, порты 80 и 443 открыты.

```bash
export MAYAK_DOMAIN=mayak.example.com
export JWT_SECRET="$(openssl rand -hex 32)"
# в compose для этого режима поставьте COOKIE_SECURE=1
docker compose --profile https up -d --build
```

Тогда наружу торчит только Caddy. Приложение внутри сети Docker слушает `0.0.0.0:8787` без своего TLS. То же самое можно собрать nginx-ом:

```nginx
server {
  listen 443 ssl;
  server_name mayak.example.com;
  # ssl_certificate и ssl_certificate_key — ваши файлы или certbot
  location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_buffering off;
  }
}
```

`proxy_buffering off` нужен, чтобы поток ответа модели не копился. При HTTPS включите `COOKIE_SECURE=1`, иначе браузер может не сохранить cookie. Секрет `JWT_SECRET` не меняйте на ходу: старые сессии станут недействительны, это нормально, но все выйдут из аккаунта.

Десктопное приложение этот режим не использует: оно поднимает свой сервер на `127.0.0.1` с `MAYAK_SINGLE_USER=1`.

## Каталог плагинов и навыков

В меню **Модели, плагины и навыки** доступны вкладки **Плагины**, **Навыки**, **Мои модели** и **Мои коннекторы**. В каталоге есть поиск и фильтр подключённых возможностей. Выберите личного агента, чтобы включить встроенный плагин или готовый навык. Навык — инструкция; он не выдаёт доступ к внешнему сервису и не заменяет подключённые инструменты.

Готовые навыки: Avito API, конкурентная среда, качество данных, истории на основе данных, генерация изображений, KPI/дашборды, финансовые модели, разбор ПО, документация OpenAI, документы, таблицы и презентации. Библиотека поставляется с приложением; новые навыки добавляются при запуске без перезаписи существующих файлов.

Карточки GitHub, Supabase, Skyscanner, Gmail, Google Calendar, Google Contacts, Google Drive, Авито и МойСклад помогают настроить **собственный Streamable HTTP MCP-сервер**: публичный HTTPS MCP-адрес и необязательный Bearer-токен. Это настройка MCP, а не встроенный OAuth-вход и не подключение напрямую к REST API. У каждого пользователя свой сервер/авторизация; доступ к нему ограничен владельцем.

Общие кабинеты Авито и МойСклад и общий инструмент stock_lookup доступны только администратору. Старые разрешения «доступен менеджерам» для этих коннекторов не действуют; даже старый агент и сохранённое подтверждение не дают доступа к ним. Администратор продолжает пользоваться своими общими кабинетами. Обычным пользователям доступны универсальные навыки каталога; внутренние отраслевые инструкции компании не выдаются.

### Скачивание GitHub агентом

Для публичного репозитория включите агенту **Код с GitHub** и отправьте ссылку в обычном чате. Этот плагин включает скачивание, чтение, поиск и редактирование файлов репозитория и выдачу архива результата. Терминал и удаление требуют отдельного плагина рабочей папки. В режиме сравнения моделей скачивание репозитория отключено. Приватные репозитории и отправка PR требуют отдельного разрешённого доступа.
