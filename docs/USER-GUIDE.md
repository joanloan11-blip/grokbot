# Маяк: справка для новых пользователей

Как собрать себе рабочего агента из плагинов, навыков и коннекторов — и получить результат,
а не «поиграться с чатом».

---

## 0. За пять минут

1. Войди по ссылке от администратора (`https://app.geminibot.ru`).
2. Нажми **«Новый агент»** → выбери готовый шаблон (например, «Аналитик конкурентов»)
   или собери своего: имя, ниша, задачи.
3. В карточке агента включи нужные **плагины** (Интернет, Рабочая папка, GitHub…).
4. Подключи **коннекторы** к своим кабинетам (Авито, МойСклад, GitHub) — если нужно.
5. Напиши первую задачу обычным языком. Агент сам вызовет инструменты и покажет, что сделал.

Всё остальное ниже — подробности с примерами.

---

## 1. Из чего состоит Маяк

| Понятие | Что это | Аналогия |
|---|---|---|
| **Агент** | персона + набор прав + модель. У каждого своя инструкция и свои подключения | сотрудник с должностной инструкцией |
| **Чат** | рабочая сессия с агентом; история хранится | переписка в мессенджере |
| **Плагин** | группа встроенных инструментов («руки» агента) | выданные доступы и оборудование |
| **Навык** | файл-инструкция, как делать конкретную работу | методичка на столе |
| **Коннектор (MCP)** | подключение к внешнему сервису через твой аккаунт | твои логины в чужих системах |

Ключевая мысль: **агент не «умнее» от того, что у него больше плагинов**. Он работает хорошо,
когда у него есть ровно те права, которые нужны для задачи, и навык, описывающий порядок действий.

### Где живут файлы и память агента

По умолчанию новый агент работает **в папке на компьютере пользователя** (кнопка «💻 Папка на
компьютере» в поле ввода): файлы и память остаются у вас и не занимают сервер. Это видно ещё в
мастере создания агента на шаге «Проверка» — там же можно выбрать «☁ В облаке на сервере».

- **Файлы.** Инструменты `workspace_*` читают и пишут в выбранной папке на компьютере. В этом
  режиме нет терминала и GitHub — они требуют облачной папки на сервере.
- **Память.** Заметки `memory_write`/`remember` сохраняются в файл `.qastom/memory/<агент>.json`
  внутри выбранной папки, а `memory_read`/`recall` читают оттуда. Общие заметки (`kind: shared`)
  лежат в `.qastom/memory/shared.json` и видны всем агентам. В облачную базу в этом режиме
  ничего не пишется — на сервере памяти нет.
- **Переключение.** Кнопка «💻/☁» в поле ввода переключает режим для конкретного агента и
  запоминается; старые заметки из облака при этом не удаляются, но в локальном режиме не видны.
- **Токены.** Память не подмешивается в каждый запрос автоматически: агент читает её только
  по необходимости (`recall`/`memory_read`), поэтому её размер не увеличивает цену каждого
  сообщения.

## 2. Плагины — что даёт агент

Включаются в карточке агента, каждый — галочка. Без галочки инструмента у агента физически нет.

| Плагин | Что умеет | Кому включать |
|---|---|---|
| 🌐 **Интернет** | поиск, свежие новости, чтение страниц | всем, кому нужны актуальные факты |
| 🗂 **Рабочая папка** | читать/писать файлы, искать по папке, терминал | тем, кто работает с файлами и кодом |
| 🐙 **Код с GitHub** | скачать репозиторий, читать, править, отдать архив или PR | разработчикам |
| 🧮 **Код** | запустить Python/JS в песочнице | расчёты, проверка гипотез |
| 📦 **Склад** | остатки и цены из МойСклад | продажам и снабжению |
| 🎨 **Картинки** | сгенерировать или изменить изображение | маркетингу |
| 🧠 **Память** | запоминать факты между чатами | долгим проектам |
| 🧭 **Команда агентов** | делегировать задачи другим агентам | сложным процессам |
| ⏰ **Расписание** | запускать задачу по времени (рутины) | регулярным отчётам |
| ✉️ **Почта** | читать подключённый почтовый ящик (IMAP) и делать выжимку | «Почтовому агенту» и почтовым делам |
| 📄 **Страницы** | собрать страницу/отчёт со ссылкой | презентации результата |
| 🛠 **Свои навыки** | агент сам пишет и правит навыки | только администратору |

**Практика.** «Аналитик конкурентов» с плагинами «Интернет» + «Код с GitHub» + коннекторами
Авито и МойСклад закрывает 90% задач по рынку: собрать объявления, сравнить цены, проверить
наличие, сделать вывод.

## 3. Навыки — методички, которые агент читает по требованию

### Что это

Файл `SKILL.md`: короткое описание + инструкция (шаги, проверки, примеры). Навык не выполняет
код — он объясняет модели **как** делать работу в твоей предметной области.

### Как это работает (важно)

1. В системный промпт агента попадают **только названия и описания** подключённых навыков.
2. Когда задача подходит, модель сама вызывает `load_skill` и получает полный текст.
3. Дальше она действует по этой инструкции.

Поэтому 10–20 навыков у агента — это нормально: контекст не раздувается, пока навык не понадобился.

### Как подключить

В карточке агента → «Навыки» → выбрать из каталога → сохранить. Всё, со следующего сообщения
агент видит их в списке.

Каталог (доступен всем пользователям):

`summary` — краткое резюме · `translate` — перевод · `avito-api` — Авито · `competitive-landscape` —
конкурентная среда · `data-quality-frameworks` — качество данных · `data-storytelling` — истории
на данных · `imagegen` — генерация изображений · `kpi-dashboard-design` — KPI и дашборды ·
`startup-financial-modeling` — финмодель · `reverse-engineer-anything` — разбор ПО ·
`openai-docs` — документация API · `documents` — документы · `spreadsheets` — таблицы ·
`presentations` — презентации.

### Свои навыки

Писать и менять навыки может **администратор** — в интерфейсе (Настройки → Навыки) или просто
положив файл в каталог данных. Агент с плагином «Свои навыки» тоже умеет: после удачного решения
повторяемой задачи он сохраняет процедуру как навык и сразу подключает её себе.

**Практика.** В чате: «найди на GitHub наборы навыков для разработчика и установи подходящие» —
агент находит репозитории, читает `SKILL.md`, сохраняет 5–10 навыков и подключает их. Проверено:
так поставили 11 навыков (`test-driven-development`, `code-review-and-quality`, `pdf`, `xlsx`,
`frontend-design` и др.) за две минуты.

## 4. Коннекторы — доступ к твоим кабинетам

### Что это

MCP-сервер: отдельная служба, которая умеет разговаривать с внешним сервисом. Агент вызывает её
инструменты так же, как встроенные.

### Два вида

- **Общие** — настроены администратором для всех (например, браузер). Видны всем.
- **Личные** — твои: подключаешь сам, только тебе и доступны. У одного пользователя до 10 штук.

Общие коннекторы к Авито и МойСклад намеренно закрыты: это кабинеты компании, менеджерам они
не выдаются. Свой кабинет подключаешь лично.

### Как подключить

1. Настройки → **Мои коннекторы** → выбрать сервис из списка (GitHub, Supabase, Skyscanner,
   Gmail, Calendar, Contacts, Drive, Авито, МойСклад) или «свой MCP».
2. Вставить **адрес MCP-endpoint** (https://…) и, если сервис требует, **Bearer-токен**.
3. Сохранить → «Проверить» → подключить нужному агенту.

Готовые карточки — это ярлыки: они не делают вход за тебя, а просят endpoint и токен твоего
сервиса. Если у сервиса нет публичного MCP, его нужно поднять самостоятельно — тогда карточка
«свой MCP» и есть твой путь.

### Куда что вставлять

В форме подключения у каждого сервиса есть подсказка, но коротко так:

| Поле | Что вставить | Где взять |
|---|---|---|
| **Название** | короткое имя коннектора, например `github-work` | придумайте сами |
| **HTTPS MCP-адрес** | endpoint MCP-сервера (Streamable HTTP), обычно заканчивается на `/mcp` | в документации MCP-сервера/сервиса; это не адрес сайта и не REST API |
| **Bearer-токен** | токен или ключ, если сервис требует авторизацию; иначе оставьте пустым | в настройках сервиса (Personal Access Token, API key и т. п.) |

Примеры: GitHub — `https://api.githubcopilot.com/mcp/` + PAT; Supabase —
`https://mcp.supabase.com/mcp?project_ref=<ref>` + Supabase Access Token. Для Google, Авито и
МойСклад публичного MCP на всех нет — в форме написано, что использовать вместо него
(встроенный коннектор или свой сервер). Токен сохраняется зашифрованным и в браузер не
возвращается.

### Что важно

- Токен хранится зашифрованным на сервере и в браузер не возвращается.
- Агент видит только те коннекторы, которые ты ему подключил, и только свои.
- Коннектор можно выключить одним переключателем, не удаляя токен.

**Практика.** Личный коннектор Авито + агент «Аналитик конкурентов»: «покажи мои объявления
с нулём контактов за прошлую неделю» → агент вызывает `items_get_items_stats_shallow`, считает
и отдаёт таблицу. Реальный результат на этих данных: «ноль объявлений с 0 контактов за неделю».

### Свой кабинет Авито — по ключам API

Раньше Авито подключалось только через MCP-сервер, который надо где-то держать. Теперь —
напрямую: Настройки → **Авито** → вставить три значения из личного кабинета
(раздел «API»): `Client_id`, `Client_secret` и `Profile_id`. Сервер сам проверит ключи и
сохранит секрет зашифрованным.

Что получает агент (плагин «Авито» в карточке агента):

- `avito_account` — кто подключён и сколько денег на кошельке;
- `avito_items` — свои объявления со статусом и ценой (активные, снятые, отклонённые);
- `avito_stats` — просмотры, контакты и избранное по объявлениям за период до 30 дней;
- `avito_balance` — баланс: реальные деньги и бонусы.

Пример: «покажи активные объявления и статистику за неделю, где больше 50 просмотров, но
ноль контактов» → агент вызывает `avito_items` и `avito_stats`, сводит таблицу и предлагает,
что переписать в заголовке.

### Свой сервер по SSH (только администратор)

Настройки → **Серверы** → указать название, хост, порт, пользователя и приватный ключ.
Ключ шифруется на сервере и в браузер не возвращается; подключение проверяется сразу —
если ssh не проходит, сервер не сохранится.

Агенту становятся доступны:

- `server_list` — какие серверы подключены;
- `server_exec` — выполнить команду (логи, systemctl, docker, деплой);
- `server_read` / `server_write` — прочитать и записать файл;
- `server_ls` — посмотреть каталог.

Опасные операции (`server_exec`, `server_write`) попадают в подтверждение, если у вас включён
режим подтверждений — как `shell` и запись в рабочую папку.

Пример: «посмотри логи nginx за последний час и скажи, сколько было 502» → агент выполняет
`journalctl`/`tail` на сервере и разбирает вывод.

### Своя почта: ежедневная выжимка

Каждому новому пользователю при регистрации создаётся агент **✉️ Почтовый агент** и рутина
**«Утренняя почта»**. Остаётся подключить ящик:

1. Настройки → **Почта** → выберите готовый сервер (Яндекс, Mail.ru, Gmail, Outlook, iCloud)
   или «Другой сервер» и заполните адрес, порт, логин и пароль.
2. Пароль — это **пароль приложения**, а не обычный пароль от почты. У Яндекса он создаётся
   в Яндекс ID → «Пароли приложений»; у Gmail нужен пароль приложения при включённой
   двухфакторной аутентификации; у Mail.ru — «Пароль для внешних приложений».
3. «Проверить подключение» покажет число писем в ящике, «Подключить» сохранит настройки.
   Пароль шифруется на сервере и в браузер больше не возвращается.
4. В блоке «Ежедневная выжимка» выберите время (по часовому поясу сервера) и включите
   «Присылать каждый день». Тут же есть кнопка «Сделать выжимку сейчас».

Что делает агент: читает только свежие письма (за сутки) через инструмент `mail_digest` и
присылает короткую выжимку — 🔴 важное, 📌 обычное, 📎 рассылки. Выжимка появляется в чате
«Расписание: Утренняя почта» и приходит в Telegram, если подключён личный бот.
Письма — недоверенные данные: агент не выполняет инструкции из писем и не отвечает отправителям.

### Личный Telegram-бот: ассистент «Джарвис»

Каждому новому пользователю создаётся агент **🎩 Джарвис** — личный ассистент, с которым
можно общаться в Telegram текстом и голосом.

1. В Telegram откройте **@BotFather**, отправьте `/newbot`, придумайте имя и username
   (username заканчивается на `bot`). В ответ придёт токен вида `123456789:AA...`.
2. Узнайте свой числовой Telegram ID: напишите **@userinfobot** или **@getmyid_bot** —
   бот ответит числом.
3. В приложении: Настройки → **Telegram** → вставьте токен и ID → «Проверить и сохранить».
4. Откройте своего бота и отправьте `/start` — можно писать текстом и голосом.

Голосовые сообщения распознаются автоматически (нужен `WHISPER_URL` на сервере), ответы
приходят текстом. Бот отвечает только владельцу (вашему Telegram ID); переписка видна в
приложении в чате «Telegram: Джарвис». Команды: `/new` — новый чат, `/help` — помощь.
Результаты рутин (например, почтовая выжимка) тоже приходят в этот бот.

## 5. Сценарии с результатом

### 5.1 Проверить, что происходит с продажами

- **Настроить:** агент «Продажи: ответ с наличием», плагины «Склад» + «Интернет», коннекторы
  МойСклад и Авито.
- **Написать:** «сравни остатки по складам с тем, что выставлено на Авито, покажи расхождения».
- **Получить:** список позиций, где товар есть, а объявления сняты (или наоборот), с числами.
  Проверено: агент вытянул 13 активных складов и сопоставил с объявлениями.

### 5.2 Разобрать чужой или свой код

- **Настроить:** плагины «Код с GitHub» + «Рабочая папка».
- **Написать:** «скачай репозиторий X, найди, где парсится цена, и объясни логику».
- **Получить:** папку `repos/X` в рабочей области, разбор файлов со ссылками `path:line`,
  при необходимости — архив на скачивание или pull request.

### 5.3 Собрать лендинг или отчёт

- **Настроить:** плагины «Страницы» + «Картинки».
- **Написать:** «сделай страницу-презентацию про фотосъёмку дроном, три блока и картинка».
- **Получить:** готовую страницу по ссылке, которую можно отправить клиенту.

### 5.4 Регулярный отчёт по утрам

- **Настроить:** агент «Исследователь», плагин «Расписание», «Интернет».
- **Написать:** «каждый день в 9:00 присылай главные новости по нашей отрасли».
- **Получить:** рутину с cron `0 9 * * *`; результат появляется новым чатом «Расписание: …».
  Проверено: `morning-news` отрабатывает ежедневно.

### 5.5 Разделить большую задачу между агентами

- **Настроить:** плагин «Команда агентов» у оркестратора, остальные агенты — с нужными правами.
- **Написать:** «собери конкурентный отчёт: рынок — аналитику, цены — продажам, вывод — тебе».
- **Получить:** каждый агент делает свою часть и возвращает результат; оркестратор сводит.
  Проверено: пересылка между агентами работает, вложенная пересылка запрещена (защита от циклов).

### 5.6 Поставить навыки из GitHub

- **Настроить:** администратор + агент с плагином «Свои навыки».
- **Написать:** «найди на GitHub навыки для разработчика и установи».
- **Получить:** навыки в каталоге, подключённые к агенту, с описаниями; работают со следующего
  сообщения.

### 5.7 Сравнить модели на одной задаче

- **Настроить:** ничего, это режим в чате.
- **Написать:** вопрос → «Сравнить» → выбрать 2–3 модели.
- **Получить:** ответы параллельно, можно «принять» лучший в основной чат.

## 6. Расходы и лимиты

- Каждый ответ агента — это токены. В интерфейсе видно расход по сообщению: модель, шаги,
  токены, стоимость.
- Администратор задаёт **дневной и недельный бюджет** пользователя и **дневной лимит токенов**.
  Когда лимит исчерпан, агент останавливается с понятным сообщением, а не «молчит».
- Модели открывает администратор: список доступных тебе моделей — в выборе модели в чате.
- Дорогие модели имеет смысл включать точечно: черновики и рутину делает дешёвая, финальный
  разбор — сильная.

**Практическое правило:** сначала дешёвая модель собирает данные инструментами, потом сильная
пишет вывод. Так дорогие токены тратятся только на то, где они реально нужны.

## 7. Что пока не работает — знай заранее

- **Оплата на сайте выключена.** Тарифы «Старт» и «Про» видны, но оплатить нельзя — доступ выдаёт
  администратор.
- **Telegram — только личным ботом.** Новый пользователь подключает своего бота в
  Настройки → Telegram (агент «Джарвис»). Старый общий бот команды остался для ранее
  привязанных чатов; без личного бота рутины приходят только в интерфейс.
- **Общие коннекторы Авито и МойСклад** доступны только администратору; остальным — личные.
- **Навыки, созданные агентом, не видны другим пользователям**, пока их не добавят в общий
  каталог. Это настройка администратора.
- **Приватные репозитории GitHub** требуют отдельного доступа — по умолчанию агент работает
  с публичными.

## 8. Безопасность и данные

- Токены коннекторов хранятся зашифрованными; в браузер после сохранения не возвращаются.
- В режиме «папка на компьютере» файлы и память агента не уходят на сервер: браузер выполняет
  чтение и запись только внутри выбранной папки.
- Агент видит только то, что ему подключили: чужие агенты, коннекторы и навыки недоступны.
- Код, который выполняет агент, идёт в песочнице без прямого интернета (доступны только пакетные
  реестры и GitHub).
- Всё, что агент делает, видно в чате: вызовы инструментов и их результаты сохраняются.
- Если что-то пошло не так — напиши в чат «продолжай» или переформулируй; история не теряется.
